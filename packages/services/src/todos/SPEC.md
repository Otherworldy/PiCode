# To-Dos

To-Dos 是项目上的工作队列，不是侧栏会话。一条 To-Do 必填标题、说明和所属项目。归属键是 `workspaceIdentity?.trim() || workspacePath`，创建后不改。项目必须是 Git 仓库根，不能是已有 worktree，也不能是仓库子目录。

## 所有者

| 状态                                        | 所有者                                                                      |
| ------------------------------------------- | --------------------------------------------------------------------------- |
| 行（状态、项目、分支、worktree、sessionId） | `TodoRepo`（`tasks-index.sqlite` 表 `todos`）                               |
| worktree / 合并结果                         | 该项目所在 Host 的 Git                                                      |
| 会话                                        | 现有 V4 `createSession`，`workingDirectory` 指向 worktree，会话仍挂在该项目 |

桌面 Main 不保存这些行。手机远控看同一条 Host。

## 状态

`todo → running → needs_review → done`。旁路 `failed`、`canceled`。`done` 只从 `needs_review` 写入。

会话状态是这一行的依据，不把用户发消息或主机重启写成失败：

- 会话还在跑（`running` / `prewarming`）：行是 `running`。若已被误标成 `needs_review` 或 `failed`，拉回 `running` 并清掉错误。
- 会话已结束（成功、中断或错误终态）：`running` 或 `failed` 进 `needs_review`，清掉轮次错误。已经是 `needs_review` 则不动，合并失败原因保留。
- 没有对应行、`done`、`canceled`、未开始，都不动。

同一项目可以同时有多条 `running`。每条用自己的分支和 worktree，不互相占用。同一行不能占两次。

## 开始

1. 占上 `running`。失败则整行改为 `failed` 并写下原因。
2. 新建行的 `id` 是 `todo-1`、`todo-2`……全局递增，删除不复用（分支可能还在）。分支和目录都用这个名字：`todo-1`、`<repo>/.worktrees/todo-1`。旧的 uuid 行仍用 `todo/<id>` 和 `.worktrees/todo-<id>`。起点是当时 HEAD。主工作区还没有提交时用 orphan 空分支，不跟别的 To-Do 分支；那些分支已经有提交也不能让下一次开始去解析无效的 HEAD。
3. 点开始时先选模型和思考等级，取消则不开始。选择不写进行里，只带进这一次 `createSession` 或继续发送。该模型有思考档位时必须选一档。会话权限为完全访问（`yolo`），执行目录是该 worktree。这个目录要写进 sessions-index 的 `workingDirectory`。列表用它标分支，过长就截断，不换行盖住下一行。右上角 Git 卡片的状态、切分支和提交都查这个目录；查主工作区的话，一点开当前分支就会变成 main。缺了就都停在主工作区。右上角 Git 卡片在 Git 仓库里常显，工作树和主工作区一样，没有未提交改动也显示。空的未跟踪文件仍不进变更列表。底部终端和右侧新建终端也用这个目录，不用主工作区。页签和标题显示该目录当前的 Git 分支；分支名还没回来，或摘要仍是别的目录时，用目录名，不用主工作区或上一条会话的分支。已经开着的终端不改目录。首条输入是说明加固定限制：不要提交、合并、变基或推送。改动留在工作区，合并时再提交。
4. 记下 `sessionId`。`failed` 且已有会话时，开始只在同一会话再发一轮，权限仍是完全访问。

进程启动不把残留 `running` 改成失败。等该工作区的 sessions-index 到达后按上面的规则对齐；对不上的会话不动。工作树保留。

## 会话删除

To-Do 不跟着会话一起删。会话没了只改这一行：

- `running` → `failed`，`error` 为「会话已删除」，`sessionId` 清空。工作树和分支留下。下次开始在同一工作树新开会话，不继续已删除的会话，也不再建工作树。
- `needs_review` 状态不变，仍可合并或完成。`sessionId` 清空，`error` 为「会话已删除」。打开会话只提示，不跳转。
- 其它状态只清空 `sessionId`。
- 没有对应行、或再通知一次，都不动。

侧栏删除先改这一行，再广播 `task_deleted`，打开着的列表才能刷到。`session.removed` 再调一次，覆盖不走侧栏的删除。

## 审阅与合并

审阅打开已有会话，diff 用现有 Git 面板。会话里不自动提交，未提交差异留给 Git 工具。合并时先把该 worktree 里已暂存和未暂存的改动提交到 To-Do 分支（能生成提交说明就用，不行就用标题），再 `mergeBranch`。主工作区必须在记录的基线分支上；冲突则停在 `needs_review` 并写原因，不自动解。工作树没有改动、相对基线也没有提交时只能 `complete`，不能合并。工作树还有未提交改动时不能 `complete`。

主工作区有未提交改动、且仍在基线分支上时，`merge` 不写 error，抛出 `code: "dirty"`。界面二选一：「用模型提交并合并」才 `merge(id, { commitDirty: true })`，用现有提交说明生成，暂存并提交当前可见的未暂存和已暂存改动，再 `mergeBranch`；「先不提交」或关掉弹窗都不改基线。变更列表滤掉的空未跟踪文件不进这次提交；提交后仍脏则写 error，不再抛 `dirty`。基线分支不对则拒绝且不提交。提交或合并失败写 error，仍是 `needs_review`。干净工作区不弹窗，直接合并。

放弃写成 `canceled`。删除 worktree 是可选项，默认不删。`restore` 只把 `canceled` 改回 `todo`，不新建工作树。

## 标签

一条可以有多个自由标签，最多 8 个，每个最多 32 字。去掉首尾空白，空的不要，大小写不同视为同一个。任何状态都能改标签，不改状态。用过的标签记在 `todo_tag_catalog`，删任务也不删目录，下次可直接选。目录是全局的，不按项目拆。列表按一个标签筛，再点一次取消。筛的是当前已加载的行。

添加在同一个输入框里完成：回车确认当前文字；英文逗号或中文逗号（打字或一次粘贴）拆成多条；输入法组字时的回车只选词，不添加。输入为空时退格删除最后一个。失焦收下还没确认的文字。已经有 8 个就不再接收。聚焦时从目录里按包含关系挑出还没选过的，点一下即添加。

## 修改

只有 `todo`（未开始，含放弃后恢复）可以改标题、说明和附件。`update` 在状态不是 `todo` 时拒绝，不改行。不传附件就保持原样；传了就整组替换。空说明仍按创建规则：没有附件就拒绝。标签不走 `update`。任务编辑窗口在点击保存且更新成功后关闭；更新失败时保持打开并显示错误。

剪贴板图片没有稳定路径。即使系统当时给了临时文件，也只存正文（`dataBase64`），不存这个路径。拖入或选中的本地文件仍只记路径。再次打开编辑时，有正文的图片要显出来。

## 验收

- 不带项目不能创建。两个项目的列表不串。
- 同一项目第二条 start 在已有 `running` 时仍开始。同一行再 start 拒绝。
- 主工作区没有提交、已有 To-Do 分支已经提交时，下一条仍能开始，工作树是空分支。
- `settle` 对未知 session 无操作。
- 删除进行中的会话：行变成失败，没有 `sessionId`，工作树还在；再开始是新会话，不建第二个工作树。
- 删除待审会话：仍是待审，打开会话被拒绝。
- 未开始可以改标题和说明。保存成功后关闭编辑窗口。已占成 `running` 后再改被拒绝。进行中仍可改标签。
- 贴进未开始任务的图片会留下正文。再打开编辑还能看到。已开始后再改附件被拒绝，原图还在。
- 删掉带标签的行后，这个标签还能再选。`Bug` 和 `bug` 只占目录一条。
- 标签输入框：回车添加，逗号和粘贴拆开，组字中的回车不添加，空输入退格删最后一个。
- 开始把当次选择的模型交给会话，行上没有模型字段。
- 已开始的 To-Do，右上角 Git 工具常显。状态、切分支和提交查该 worktree。主工作区也常显，没有未提交改动时不隐藏。
- 会话在 worktree 时，新开的终端用这个目录。标题是该目录当前的 Git 分支；分支名还没回来时用目录名，不用主工作区的分支。已经开着的终端不改目录。
- 会话还在跑时行是进行中，即使之前被记成失败或待审。会话结束后是待审，不是失败。用户再发一条消息把会话拉回运行后，行回到进行中。
- 工作树没有改动且没有提交时不能 merge，只能 complete。工作树有未提交改动时，合并先提交这些改动再合并；此时不能 complete。
- 脏工作区直接 merge 抛 `dirty` 且不写 error。只有选「用模型提交并合并」才传 `commitDirty`；「先不提交」不改基线。`commitDirty` 先提交基线再合并；基线分支不对时不提交。
