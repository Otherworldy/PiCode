# 拉取模型

「编辑 AI 服务」弹窗里从端点读取模型列表的行为。

## 行为

点击「从端点拉取」不再把 `discover` 结果整体追加进草稿，而是打开模型选择弹窗：先展示端点返回的全部模型，由用户勾选后再导入。

- 弹窗打开时发起一次 `mutate({ action: "discover" })`，结果只用于该弹窗。
- 端点返回的模型与草稿现有 `models[].id` 取差集得到「可添加集合」。
- 已在草稿里的模型仍然展示，标「已添加」并禁用勾选；它不参与全选三态。
- 可添加数量 ≤ 20 时默认全选；> 20 时默认只选前 5 个，并给出提示条。
- 搜索按 ID 与别名过滤，「只看未添加」只影响可见性，都不改变已选集合。
- 主按钮文案带数量（「导入 N 个模型」），选择为空时禁用。
- 取消、关闭、Esc 一律丢弃选择，草稿保持原样。

## 所有者

- `ProviderSetupDialog` 持有草稿（`ProviderDraft`），并且是唯一写入方。
- 选择弹窗持有 `discovered`、`selectedIds`、`query`、`onlyNew` 四项局部状态，弹窗卸载即丢弃，不进入草稿、不落盘。
- 只有「导入」这一步把选中的模型经 `defaultChosen()` 映射后一次性 `onChange` 写回草稿；再次取差集，连点两次不会产生重复模型。
- 落盘仍只发生在「保存服务」的 `upsert`。

## 事件顺序

```text
点击拉取 → 打开弹窗 → discover（Host） → 局部 discovered
        → 勾选（只改 selectedIds） → 导入 → 差集 + defaultChosen → ProviderDraft
        → 保存服务 → models.json
```

`discover` 结果按连接字段（`baseUrl` + `api` + `apiKey`）做请求级缓存，「测试连接」与选择弹窗共享同一次结果；连接字段变化后自然失效，重试走强制刷新。

## 失败语义

- `discover` 失败：弹窗内展示失败态与「重试」，不阻塞手填模型 ID 的主路径。
- 端点返回空列表：展示空态，引导手填或换协议。
- 全部已添加：展示完成态，主按钮不可用。

## 验收

- 端点返回 42 个模型、草稿为空：默认选中 5 个，出现提示条，导入后草稿恰好新增 5 个。
- 草稿已有 `deepseek-r1`：该行标「已添加」且不可勾选，全选不会把它算进分子或分母。
- 勾选后点「取消」：草稿与 `models.json` 都不变，重开弹窗重新读取端点。
- 搜索与「只看未添加」组合过滤后，计数仍反映真实已选数量，而不是可见数量。
- 窄屏（< 640px）：工具条换行、token 胶囊换行、底部按钮等宽两列，导入仍可点。
