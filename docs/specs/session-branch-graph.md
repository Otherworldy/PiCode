# 会话分支图谱

会话分叉关系的关系图谱。入口在会话头部右侧按钮组，弹窗展示当前会话所在的整棵分叉树。

## 行为

- 入口是会话头部右侧的图标按钮，`aria-label` 走 i18n。没有当前会话（草稿态）时按钮禁用，tooltip 写明原因。点击只打开弹窗，不改变当前会话。
- 图谱范围是「当前会话所在的分叉家族」：先向上追到根，再取该根的全部后代。同 workspace 内不相连的其它家族不显示；同源兄弟分支必须出现，否则就看不到并行试过哪些方案。
- 连线只表达用户分叉（`forkedFromTaskId`）。子智能体、侧聊、workflow actor 的 `parentSessionId` 不进入图谱。
- 节点按层级自上而下排列，同层按创建顺序从左到右。父节点水平居中于子节点跨度。
- 节点显示标题、状态点（运行中 / 出错 / 已完成 / 已删除）、最近更新时间；当前会话带「当前」标记，运行中带「运行中」标记。固定节点宽度会截断长标题，hover 或键盘聚焦节点时用 Tooltip 显示完整标题。
- 点击节点把当前会话切换过去并关闭弹窗。切换复用会话列表原本的选择链路（`handleSelectTask`），语义与点击侧栏任务行一致，包含模型重建期的拦截与未读清理。
- 已删除会话显示为虚线边框节点并带「已删除」文字标记，不可进入；点击只提示「该会话已删除，无法打开」，不改变当前会话。
- 「显示已删除」开关默认开启。关闭后隐藏已删除节点，其子节点改挂最近的可见祖先，对应连线改为虚线。
- 画布支持滚轮缩放、拖拽平移与「适配」重置视图；`Esc` 关闭弹窗。

## 所有者

- 分叉关系的事实源是 Pi 会话文件头的 `parentSession`（父会话 jsonl 路径）。host 在扫描会话目录时把它解成 `parentSessionId` 挂到 sessions-index 摘要上；tasks-index 再落成 `forked_from_task_id`。UI 只读，不自行推断父子，也不在打开弹窗时补写。
- tasks-index 的写入规则：新行走基线插入；已有行只在 `forked_from_task_id` 为空时补写（旧版本没有落过这个字段），有值时不覆盖；运行态 snapshot 不带 parent 时保留已存值，不能把来源冲掉。旧数据靠重启后的首次 sessions-index 快照补齐。
- 已删除会话的标题等展示信息只能来自 tasks-index tombstone：删除会物理删除会话本体，sessions-index 不再有该行。图谱走 `listDeletedTasks` 读取 tombstone meta，不复用只返回 id 的 `listDeletedTaskIds`。
- 弹窗每次打开时按当前 workspace 拉取一次：active / pinned / archived / deleted 四路并集。图谱是只读视图，不改写任何 task 状态、不写 store。
- 开关状态与缩放平移属于弹窗局部 UI 状态，不持久化。
- 父会话在 tombstone 之外完全缺失（历史行被清理）且四路分区都读到时，图谱按子节点的 `forkedFromTaskId` 合成一个占位节点，标题用「已删除的会话」，避免整支分支凭空失去起点。占位节点不计入「已删除」统计。
- 从节点切换会话时把该行的 `unreadAt` 一并交给选择链路，与侧栏点任务行一样清未读蓝点。

## 失败

- 某一路 task 分区读取失败：保留已拿到的行继续展示，弹窗内提示读取不完整，不把失败当成空图。此时不合成占位父节点：父会话缺失分不清是已删除还是没读到，把活着的会话画成「已删除」比缺一个节点更糟。
- 当前会话不在任何分叉关系里：只显示当前会话一个节点，不算错误态。
- 当前会话已不存在于任何分区（例如刚被其它窗口删除）：保留上次打开时的数据并提示，不自动切换到别的会话。
- 当前会话已删除且关闭「显示已删除」：画布里没有当前节点，用提示条说明原因，不改写当前会话选择。
